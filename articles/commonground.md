## Architecture and data model

The implementation separates Agent identity, Turn lifecycle, Turn-owned semantic records, and a project ledger. PostgreSQL stores agents and credentials, turns and claim state, semantic-record references, and ledger events. Semantic rows contain a role, turn sequence, and CardBox reference rather than the payload itself; the repository declares CardBox as a git submodule. The inspected shallow checkout did not initialize that submodule, so its storage and retention behavior are outside this review.[[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)] [[CardBox submodule declaration](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/.gitmodules)]

A semantic row is keyed by project and record ID, sequenced within a turn, and linked to a CardBox project and ID. The SQL schema enforces that the payload reference uses the same project and keys records to a project/turn pair. The ledger separately records event sequence, project, event type, subject, actor, optional cause, timestamp, note, annotations, and an optional payload reference.[[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)]

## Write, update, delete, and retrieval

**Write.** A worker can append a semantic record only while holding an active claim for its turn. The kernel checks that the payload reference belongs to the same project and exists in CardBox, then inserts a new sequenced reference. The work-memory-report API accepts a manifest with records, optional source references, and an optional final payload; the SDK stores payloads in CardBox and turns the submitted report into a closed work-report turn with semantic references.[[semantic kernel](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/kernel/semantic.py)] [[SDK report path](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/sdk/composites.py)] [[HTTP reference](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/docs/en/reference/http.md)]

**Update and correction.** Semantic records are appended and have no inspected update operation. Turn lifecycle fields do change as turns are claimed, suspended, resumed, or closed; those lifecycle updates are not edits to previously stored semantic content. A corrected fact can be represented as a later record, but the inspected kernel does not define supersession, temporal validity, or correction selection semantics.[[semantic kernel](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/kernel/semantic.py)] [[lifecycle kernel](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/kernel/lifecycle.py)] [[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)]

**Delete.** The inspected HTTP routes expose no semantic-record or payload deletion operation. The schema has a cascade from turns to semantic records, but that is not a public deletion workflow or evidence that payloads in CardBox are removed. Retention, erasure, and backup behavior for payloads remain unknown because the CardBox implementation was not inspected.[[HTTP routes](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/service/routes.py)] [[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)] [[CardBox submodule declaration](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/.gitmodules)]

**Retrieval.** The SDK fetches a turn’s semantic records in turn-sequence order and hydrates their CardBox references. Ledger feeds support project-wide sequence reads or indexed reads scoped to a turn or agent, with an after-sequence cursor and limit. These are identity/sequence reads; the inspected kernel has no embedding, vector, full-text, or semantic search path.[[SDK context and feeds](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/sdk/composites.py)] [[repository reads](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/repositories.py)] [[README](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/README.md)]

## Scope isolation

Project identity is carried in Agent and Turn references, authenticated against an active bearer credential, and matched against request identity. SQL keys pair project IDs with record/turn IDs, semantic payload references are constrained to the same project, and feed indexes include project, scope kind, and scope ID. These are source-visible isolation mechanisms. No adversarial cross-project workload was run, so isolation behavior in a deployed configuration was not measured.[[authentication](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/service/auth.py)] [[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)] [[repository reads](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/repositories.py)]

## Provenance and evidence

Ledger events associate a subject with an actor and optional cause, and can retain notes, annotations, and payload references. Turn cause and parent/child lineage support reconstructing why work was dispatched. Work-memory reports accept per-record `source_refs`, which are included in the stored CardBox payload. This provides event and payload lineage, but does not itself check factual support, create user-facing citations, or assign a trust state or validity interval to each fact.[[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)] [[ledger writes and scope index](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/repositories.py)] [[report normalization](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/sdk/composites.py)]

## Efficiency and observability

Sequence indexes and bounded feed reads support incremental inspection by project, agent, and turn. Writes use PostgreSQL transactions and the reviewed paths avoid model inference or embedding generation in the kernel. The API accepts trace context and operation metadata, while ledger notes and annotations can preserve operation context; the selected kernel methods discard trace context. No latency, token, cost, or storage measurements were collected.[[repository reads](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/repositories.py)] [[routes and trace parsing](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/service/routes.py)] [[lifecycle kernel](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/kernel/lifecycle.py)] [[SDK](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/sdk/composites.py)]

## Limits and unknowns

This review covers the README, selected architecture/API documentation, PostgreSQL schema, semantic and lifecycle kernels, SDK context/report paths, repository reads/writes, and request authentication at the verified head. It does not cover every adapter, integration, operational deployment, error path, or the CardBox submodule’s internal behavior. The README describes v3r1 as a preview and states it is not backward-compatible with the earlier v1 preview.[[README](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/README.md)] [[schema](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/CommonGround/infra/postgres.py)] [[HTTP reference](https://github.com/Intelligent-Internet/CommonGround/blob/10b50ddb0fb4f0d5b4a58e841d6f40b52a3cbd5b/docs/en/reference/http.md)]

No CommonGround runtime, tests, or benchmarks were run. Measured recall quality, correction selection, deletion completeness, isolation under deployment, evidence support, latency, write-to-recall delay, token/cost use, and storage efficiency remain unknown.
