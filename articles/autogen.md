## Summary

AutoGen is a multi-agent application framework whose Python memory API lets an application attach stored content to model context. The common contract provides add, query, context-update, clear, and close operations; storage and retrieval behavior belongs to each implementation. Included options range from an in-process chronological list to ChromaDB, Redis, Mem0, and an experimental text canvas. This review inspected source and documentation only; no runtime or benchmark results were measured. [[README.md](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/README.md)] [[Memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)]

## Who and what

The repository is published by Microsoft and describes AutoGen as a framework for building multi-agent AI applications. The pinned README says the project is archived and no longer actively maintained by Microsoft, and recommends Microsoft Agent Framework for new projects. AutoGen has layered Core, AgentChat, and Extensions APIs; the memory package is a framework component within that broader agent framework. [[README.md](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/README.md)] [[memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)]

## Architecture and data model

**Code observation.** `autogen_core.memory` defines `MemoryContent` as content (string, bytes, dictionary, or image), a MIME type, and optional arbitrary metadata. `MemoryQueryResult` returns a list of such items. The abstract `Memory` component requires `update_context`, `query`, `add`, `clear`, and `close`. It intentionally leaves storage and retrieval strategy to implementations; there is no common ID, scope, correction, provenance, or targeted-delete field or method in the interface. [[memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)]

**Code observation.** `ListMemory` keeps `MemoryContent` objects in a Python list. Its query returns every item, and its context update appends all items as a numbered system message in chronological order. The list is available through a mutable `content` property; `clear` replaces it with an empty list. This is simple process-local storage, not a persistent index. [[ListMemory](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_list_memory.py)]

**Code observation.** `AssistantAgent` accepts one or more memory components. Before model inference it calls each memory’s `update_context`; results are emitted as `MemoryQueryEvent` events. The agent thus provides a first-class injection and event-reporting hook, while each memory implementation chooses which content to add and how to format it. [[AssistantAgent](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-agentchat/src/autogen_agentchat/agents/_assistant_agent.py)]

**Code observation.** The Extensions package includes a ChromaDB vector-memory adapter, Redis memory, Mem0 integration, and a text-canvas example. ChromaDB config selects persistent local or HTTP storage, collection, embedding function, top-`k`, score threshold, and distance metric. Redis config selects endpoint, index/prefix, embedding model, top-`k`, threshold, and either semantic or sequential retrieval. The text canvas injects its current file snapshot; its own `query` and `add` methods are empty/no-op because edits are delegated to canvas tools. [[ChromaDB configuration](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chroma_configs.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)] [[Text canvas adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/canvas/_text_canvas_memory.py)]

## Write, update, delete, and retrieval

**Write and retrieval.** The core API exposes `add(MemoryContent)`, and applications or task-specific components decide what to write; the common memory contract does not itself extract facts from conversation. `ListMemory` appends items and returns all of them. ChromaDB stores extracted text and metadata with a generated UUID, then queries vector similarity with configured `k`; it attaches score and ID to returned metadata and can filter by a configured threshold. Redis supports semantic nearest-neighbor search or recent sequential retrieval. Mem0 delegates writes and search to its client and uses a configured result limit. These are different backend behaviors behind a shared interface, not one uniform ranking policy. [[memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)] [[ListMemory](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_list_memory.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)] [[Mem0 adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/mem0/_mem0.py)]

**Context integration.** In the assistant path, memory updates the model context immediately before inference. ChromaDB, Redis, and Mem0 use the last context message as their query and add returned memory text as a system message; ListMemory injects all stored entries. AssistantAgent emits an event containing returned memories, making retrieval results observable in the agent message stream. The generic interface does not prescribe query formation, prompt format, filtering, or result limits. [[AssistantAgent](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-agentchat/src/autogen_agentchat/agents/_assistant_agent.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)] [[Mem0 adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/mem0/_mem0.py)]

**Update and delete.** The shared contract has no item-level update or delete operation; it offers only full `clear`. ListMemory can be edited directly through its exposed mutable list. ChromaDB assigns UUIDs on add and supports full collection clear; its implementation also has a separately gated reset operation, but no common targeted-delete method. Redis clear removes the current history contents. Mem0 clear delegates to `delete_all` for the configured user. These implementation-specific clear paths do not establish common correction semantics or deletion completeness across replicas, backups, or derived indexes. [[memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)] [[ListMemory](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_list_memory.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)] [[Mem0 adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/mem0/_mem0.py)]

**Scope and isolation.** Scope is adapter configuration rather than a field enforced by the common contract. Mem0 uses a configured `user_id`, but creates a random UUID when one is omitted; callers needing stable identity must supply it. ChromaDB can separate data through persistence paths and collection names, and Redis through index/prefix configuration, but those choices are not authentication or ownership checks in AutoGen’s memory interface. ListMemory instances are separate in-process lists. The reviewed code does not establish tenant isolation at a deployment boundary. [[memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)] [[Mem0 adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/mem0/_mem0.py)] [[ChromaDB configuration](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chroma_configs.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)]

## Metric-domain evidence

**Code observations, not measurements.** Answerable recall and abstention depend on each backend’s retrieval policy and subsequent model behavior; the inspected interface does not define evaluation or abstention. ListMemory returns all stored content; vector adapters return bounded results using their configured limits and thresholds. No retrieval workload was run. [[ListMemory](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_list_memory.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)]

The core content type supports free-form metadata, but does not standardize source references, confidence, authorship, valid time, or mutation history. ChromaDB adds generated IDs and similarity scores to returned metadata; Mem0 maps client-provided scores, timestamps, and categories when available. Those fields do not amount to a framework-wide evidence or citation contract. [[memory interface](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-core/src/autogen_core/memory/_base_memory.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Mem0 adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/mem0/_mem0.py)]

The adapters expose configuration knobs and log initialization, add, query, and clear failures. AssistantAgent emits memory query events with the returned contents. The inspected memory sources do not provide shared latency, token, cost, storage, correction, deletion, or isolation metrics. Configured `k`, thresholds, and limits describe behavior, not measured quality or efficiency. [[AssistantAgent](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-agentchat/src/autogen_agentchat/agents/_assistant_agent.py)] [[ChromaDB adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/chromadb/_chromadb.py)] [[Redis adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/redis/_redis_memory.py)] [[Mem0 adapter](https://github.com/microsoft/autogen/blob/8390985108cb1e3881f5f7297765758d8ad2540c/python/packages/autogen-ext/src/autogen_ext/memory/mem0/_mem0.py)]

## Limits and unknowns

This review inspected the Python Core memory interface and ListMemory, AssistantAgent’s memory integration, and ChromaDB, Redis, Mem0, and text-canvas adapters at the pinned head, plus the repository README and security policy. It did not inspect every adapter, .NET implementation, task-centric memory sample, or deployment. The source review cannot establish real retrieval quality, safe tenant isolation, correction behavior supplied by application code, deletion completeness, latency, token use, or cost. The repository has been archived; the README states Microsoft is not providing fixes, features, or support.
