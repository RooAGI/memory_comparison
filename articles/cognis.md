Cognis describes itself as a cloud-native Agent OS and controller for self-hosted agents. It owns agent, user, project, conversation, workflow, and runtime policy orchestration; persistent memory is delegated to the companion Mnemory service. This review covers Cognis’s memory integration rather than Mnemory’s internal storage or retrieval implementation.[[README](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/README.md)]

## Architecture and data model

The controller resolves a provider-neutral per-turn memory policy from an agent’s selected backend and options. The Mnemory backend defines three modes: full auto (bootstrap, automatic recall and remember, tools), proactive (bootstrap and tools without automatic recall/remember), and on demand (tools only, without bootstrap or automatic traffic). A SHA-256 fingerprint labels the frozen policy; it does not describe what Mnemory stored.[[backend modes](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/backends/memory/mnemory.py)] [[policy model](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/policy.py)]

Mnemory is the durable memory owner. Cognis’s provider makes authenticated HTTP requests for recall, remember, memory CRUD/search, and artifact operations; Cognis’s relational database also has a `remember_queue` table for pending write work. In production wiring the queue is database-backed, stores event/session identifiers and hashes so it can read the source event later, and supports retries across restarts; the in-memory fallback is for narrow test setups, not the production mode.[[provider](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/mnemory.py)] [[queue](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/remember_queue.py)] [[queue row](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/store/models.py)]

## Write, update, delete, and retrieval

**Write.** In full-auto mode, Cognis enqueues eligible completed user/assistant turns for Mnemory. The worker reads the event from Intaris and sends it to Mnemory. A separate explicit trusted-evidence path can send a strict user-event envelope bound to the persisted event’s ID/hash and user, owner, session, conversation, and turn identities. That path is gated by configuration and an owner allowlist that defaults empty; the source says ordinary auto-remember is not a substitute for historical reconciliation.[[agent loop](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/agent_loop.py)] [[queue](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/remember_queue.py)] [[trusted evidence contract](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/evidence.py)] [[compatibility notes](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/docs/trusted-semantic-compatibility.md)]

**Update and delete.** The controller exposes explicit memory add, batch add, update, and delete tools which call Mnemory; a delete by ID is issued to Mnemory under the current identity. The adapter also uses an `If-Match` revision for alias-based update/delete operations where a revision is available. Bootstrap identity replacement adds the new pinned identity memory and removes labeled prior entries, with guarded best-effort cleanup for a single unambiguous legacy match. These are integration paths, not proof of correction accuracy or complete erasure in the external service.[[memory tools](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/tools/builtin/memory.py)] [[provider update/delete](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/mnemory.py)]

**Retrieval.** Automatic recall is performed during context preparation when the frozen policy enables it. The controller requests Mnemory’s search mode with a bounded query, session ID, labels, optional context, and TTL; the provider retries boundedly and logs counts/latency metadata. Agents can also call semantic search, multi-angle AI find, or synthesized ask tools; their descriptions identify find as two extra LLM calls and ask as the most expensive, at three calls. Cognis does not implement Mnemory’s ranking algorithm.[[context recall](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/context.py)] [[provider](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/mnemory.py)] [[tool definitions](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/tools/builtin/memory.py)]

## Scope isolation

The provider requires an explicit user identity or scoped runtime context to form a service JWT. Requests carry the user as JWT subject and, when available, agent ID and owner headers; missing identity causes failure instead of silently using a global identity for ordinary operations. Cognis passes the Mnemory session ID and labels for recall. For managed external conversations, policy disables ambient automatic recall and remember; the non-bypassable tool filter denies mutation tools and permits search tools only when explicitly allowed by the conversation policy. These controller checks do not independently establish isolation inside Mnemory or every deployment path.[[provider identity](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/mnemory.py)] [[managed policy](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/external_managed_policy.py)] [[context recall](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/context.py)]

## Provenance and evidence

Ordinary queued writes retain pointers to durable Intaris events rather than copying the conversation text into the queue. The optional trusted-evidence contract binds a strict single-user-message request to a canonical event hash and identity tuple and classifies terminal versus uncertain outcomes. The queue’s evidence marker and policy metadata describe admission and delivery lifecycle, not a review of the truth of the resulting memory. Cognis delegates stored-memory provenance and any answer-level citations to Mnemory and downstream consumers.[[queue](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/remember_queue.py)] [[evidence contract](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/evidence.py)] [[trusted evidence lifecycle](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/trusted_evidence.py)]

## Efficiency and observability

The provider uses bounded retry and circuit-breaker handling for calls. Ordinary remember treats a transport failure as outcome-unknown and disables automatic retry to avoid duplicate writes; queue handling and the dedicated trusted route carry their own retry/terminal-outcome rules. Queue depth, retry, drop, success, replay and trusted-evidence outcome/age metrics are defined. Logs record operation type, lengths/counts and latency/statistics rather than putting the recall query or remember payload in those particular log fields. The NFR guide documents health status, provider latency and queue depth/oldest age. These source-level instruments do not supply performance measurements for this review.[[provider](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/providers/memory/mnemory.py)] [[queue metrics](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/remember_queue.py)] [[evidence metrics](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/cognis/core/trusted_evidence.py)] [[operations guide](https://github.com/fpytloun/cognis/blob/7f1d5aee813d4a9e6a67d4703e45ccb90ab0eb80/docs/specs/13-nfr-operations.md)]
