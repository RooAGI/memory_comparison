## Summary and architecture

Echo Agent is an AI agent application with a Python Runtime, desktop application, and persistent cross-session memory. The upstream documentation distinguishes the independent Runtime memory described here from the desktop application’s separate embedded memory implementation. The Runtime’s memory layer organizes working context, session episodes, semantic facts, and archival records.[[README](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/README.md)] [[memory concept](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/docs/concepts/memory-system.md)] [[memory guide](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/docs/guides/memory-management.md)]

Runtime `MemoryEntry` records contain type (USER or ENVIRONMENT), tier, key, content, tags, source session, created/updated times, importance, access count/time, embedding and episode identifiers, version, supersession pointer, source label, and a pinned flag. `Episode` records hold a session key, summary, message range, entity IDs, importance, and creation time. Working memory is an in-process buffer; semantic records live in per-type JSON files, while an optional storage backend holds episode, contradiction, and vector data. The code identifies `user_memory.json`, `env_memory.json`, and a forgotten-fingerprint file under the configured memory directory.[[types](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/types.py)] [[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[episodes](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/tiers.py)] [[SQLite backend](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/storage/sqlite.py)]

The Python Runtime constructs the store with the configured scope policy and memory directory. The documented default scope policy is session based; a cross-channel owner option can map explicitly bound one-to-one senders to a shared owner scope. The desktop uses a separate implementation, so these Runtime findings should not be generalized to it.[[configuration](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/config/schema.py)] [[Runtime wiring](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/agent/loop.py)] [[desktop memory documentation](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/docs/desktop/knowledge-memory.md)]

## Write, update, delete, and retrieval

**Write and consolidation.** The `memory` tool supports add, search, replace, remove, list, and contradiction actions. Add creates a typed entry and the store validates/sanitizes content, deduplicates exact same-scope records, merges compatible conflicts, enforces per-type capacity, persists JSON atomically, and queues embedding work. Background consolidation summarizes episodes, extracts candidate facts, checks conflicts, promotes accepted facts, applies decay/retention, reflects on conflicts, and renders a human-readable memory view. Documentation says consolidation is asynchronous, so a reply can precede durable long-term extraction.[[memory guide](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/docs/guides/memory-management.md)] [[memory tool](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/agent/tools/memory.py)] [[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[consolidator](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/consolidator.py)]

**Update and correction.** Replace is routed through `MemoryService`, which checks target scope, environment-write policy, forgotten-memory barriers, and provenance priority before updating the existing entry. The store changes content, tags, source, and update time, then queues a replacement embedding. Same-key conflict handling can append a new version and mark the prior entry superseded. Lower-priority sources cannot silently replace higher-priority facts through the guarded service path; explicit override is available for privileged correction. These controls are code observations, not evidence of correction accuracy.[[service](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/service.py)] [[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[types](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/types.py)]

**Delete and retention.** Remove checks scope and provenance before deleting the active entry. An explicit user-forget path writes a fingerprint/time barrier so older episode material cannot simply recreate that fact; episode visibility and consolidation also check the barrier. Deletion removes the semantic record and schedules associated vector cleanup. Maintenance can archive low-importance or superseded entries and purge expired episodes. The review did not verify physical erasure from backups, historical conversation logs, or every external copy, so end-to-end deletion guarantees remain unknown.[[service](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/service.py)] [[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[episodes](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/tiers.py)] [[consolidator](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/consolidator.py)]

**Retrieval.** The hybrid retriever filters by configured memory scope and lifecycle eligibility, builds a bounded candidate pool, ranks with BM25 and optional vector similarity, combines rankings with reciprocal rank fusion, applies importance, and can rerank a bounded top set. It admits results only when there is a discriminative lexical match or a vector hit over the configured similarity floor; retrieval limits ordinary output to five memory entries and three episodes. Embedding timeout/failure and reranking failure degrade to lexical/RRF behavior rather than block the turn. Semantic memory snapshots are bounded by entry and character limits; pinned entries receive priority, while the long tail is available through query-driven recall.[[retrieval](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/retrieval.py)] [[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[forgetting](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/forgetting.py)]

## Scope isolation

The default Runtime configuration selects the `session` scope policy. Under it, session-owned USER facts are visible only in their memory scope; unowned USER records fail closed, while explicitly tagged global facts and ENVIRONMENT facts follow separate visibility rules. Cross-channel sharing is an opt-in owner mapping for configured principals in direct messages; groups and unbound senders remain session scoped. Scope is applied in store visibility and retrieval paths. This is source-level evidence for the inspected Runtime paths, not a deployed multi-tenant security guarantee; no isolation workload was run.[[configuration](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/config/schema.py)] [[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[retrieval](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/retrieval.py)] [[Runtime wiring](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/agent/loop.py)]

## Provenance and evidence

The `source` field distinguishes user-stated, consolidated, model-inferred, and legacy records; write paths assign or validate that source, and the provenance guard ranks it during replacement/removal. Entries retain source session and timestamps, and episodes retain session and source-message ranges. The service can append bounded JSONL audit records with actor, operation, entry, scope, source, result/reason, and timestamp. These fields help trace memory mutations, but the semantic entry schema does not itself hold a citation or source-document evidence object, and no generated answers were checked for factual support.[[types](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/types.py)] [[service](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/service.py)] [[episodes](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/tiers.py)]

## Efficiency and observability

Code uses atomic file replacement, per-target file locking, bounded retrieval pools and quotas, snapshot caps, best-effort embedding queues, model timeout budgets, and fallback behavior. The optional SQLite backend serializes operations and enables WAL; vector lookup uses a normalized in-memory matrix. Store/service paths emit logs for retrieval degradation, storage synchronization, write rejection, and consolidation failures; an optional audit file can record mutations. These are implementation details only; latency, token use, cost, throughput, and storage overhead were not measured.[[store](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/store.py)] [[retrieval](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/retrieval.py)] [[vectors](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/vectors.py)] [[SQLite backend](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/storage/sqlite.py)] [[consolidator](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/consolidator.py)] [[service](https://github.com/fuyuxiang/echo-agent/blob/15f0802faf6eeb37bbac217894f87a05944335cd/echo-agent-runtime/echo_agent/memory/service.py)]
