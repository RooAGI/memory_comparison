## Architecture and data model

**Code observation.** The canonical dataset is a manifest plus ordered `records-NNNN.jsonl` shards under `OpenAIDatabase/data/memory/records/`. The sharding contract describes this as one logical source of truth; the CLI deterministically builds and validates plans, and its writer stages a complete shard set, fsyncs files/directories, installs it, then reloads and validates the manifest and records. Generated agent-memory views are a separate build mode. ([sharding contract](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory.sharding.json); [memory CLI](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory.py))

V2 records include an ID, memory key, kind, statement, status, typed scope, source reference and observation time, optional evidence hash, valid-time interval, recorded-time timestamp and transition history, confidence/importance, verification state and evidence references, aliases/tags/negative triggers, sensitivity, conflict/supersession fields, and a canonical content hash. The architecture document identifies candidate, active, disputed, and retired records in the canonical store and labels legacy active/candidate/curation trees as read-only migration evidence. ([memory schema](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory.schema.json); [personal context architecture](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/docs/PERSONAL_CONTEXT_ARCHITECTURE.md))

## Write, update, delete, and retrieval

**Write and update code observations.** Mutations use a validated envelope with operation, idempotency key, base commit SHA, actor, source, authorization, target scope, payload, valid time, sensitivity, and reason. The supported operations are add, update, retire, and dispute. Adds reject a second active record for the same key and scope; updates retire the prior record, append a transition, and create a successor with a supersession link. Envelopes labeled `raw_import` or `model_inference` are rejected for canonical persistence by the mutation policy. Applying a mutation requires explicit write guards and the designated Automation C branch; the source code reports no direct main write. ([mutation implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_mutation.py); [mutation policy](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory-mutation-policy.json); [memory CLI](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory.py))

**Update, retirement, and deletion.** Update and retire append transition details (transaction ID, operation, time, actor, prior/next status, validity boundary, and reason); update also adds a successor record. No physical delete operation appears in the inspected mutation operation set. The forgetting policy explicitly defines retirement as retrieval exclusion rather than history deletion, and the schema forbids canonical business-record rewrite in task. Historical bytes therefore remain in the canonical history under the inspected lifecycle. ([lifecycle implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_lifecycle.py); [forgetting implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_forgetting.py); [memory schema](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory.schema.json))

**Retrieval.** The CLI supports filters for record ID, memory key, kind, scope, tags, keyword, valid-time `--as-of`, recorded-time `--recorded-as-of`, and result limit. Current queries admit active and effective records by default; inactive records may be included for audit but are not answer eligible. Historical queries project status through recorded transitions and valid-time intervals. The decision layer returns `UNKNOWN` with a reason and missing conditions when it cannot find eligible evidence. Keyword search may use an in-memory lexical routing index to prefilter candidates; the route is accepted as a complete-substring prefilter only when its completeness condition holds. ([memory CLI](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory.py); [retrieval implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_retrieval.py); [forgetting implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_forgetting.py))

## Scope isolation and provenance

**Code observation.** Record scopes are global, project, task, or conversation. Query scope is an optional filter; the query implementation does not itself require callers to supply one. Mutation policy allows explicit-user sources in all four scope types and repository-evidence sources only in project/task scopes. This demonstrates scope-aware records and filtering, but the inspected local CLI code does not establish authenticated tenant or principal isolation. ([memory CLI](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory.py); [memory schema](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory.schema.json); [mutation policy](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory-mutation-policy.json))

Source metadata records source type, reference, observation time, and optional SHA-256 evidence hash. Verification records carry a state, method, evidence references, verification timestamp, and rationale. The mutation envelope separately records actor and authorization references; repository-evidence mutations require an evidence hash, while the policy rejects raw-import and model-inference sources from canonical mutation. These fields provide provenance structure, but do not by themselves prove that every statement is supported by its referenced evidence. ([memory schema](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory.schema.json); [mutation implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_mutation.py); [mutation policy](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/memory-mutation-policy.json))

## Efficiency and observability

**Code observation.** The retrieval contract sets a default budget of one discovery object and at most two indexed-fact content fetches, zero recursive full-tree scans, at most three raw-expansion fetches, and three request attempts within a 120-second retry budget. The GitHub Contents reader requests commit-scoped content, requires an ETag, reuses a cached response with conditional requests, and drops prior cache entries for that repository path when the commit changes. The lexical index routes to at most two shards by default. These are source-level design limits, not measured performance. ([retrieval contract](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/config/evaluation/memory_retrieval_performance_v1.json); [retrieval implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_retrieval.py))

The CLI emits structured JSON results and query traces with scanned, filtered, excluded, and matched counts. A local build/query benchmark command is present, but this review did not execute it. The inspected source does not provide measurements for answer quality, latency, tokens, cost, write-to-recall delay, or storage efficiency. ([memory CLI](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory.py); [retrieval implementation](https://github.com/LinzeColin/AgentDatabase/blob/e9acee95271d828167d90f0985aaad3c9cb9f7dd/OpenAIDatabase/scripts/memory_retrieval.py))

## Limits and unknowns

This is a bounded source review of selected documentation, schema, and Python implementation at the pinned main head. It does not establish runtime correctness, answer quality, measured retrieval performance, actual deletion/erasure, or authenticated scope enforcement. Source-level scope filters are not an isolation test. The repository includes a separately retired MemoryAtlas application; it is not assessed here as an active memory service. Anything not directly verified in the inspected paths remains unknown.

The official repository README, OpenAIDatabase README, and personal-context architecture document were checked for a published contact email. None was found in those checked documents; the JSON record stores `null` and the exact pinned root README URL that was checked.
