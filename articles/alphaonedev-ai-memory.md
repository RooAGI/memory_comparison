## Summary

AlphaOne ai-memory is a self-hosted Rust memory substrate with MCP, HTTP, and CLI interfaces. The default local path uses SQLite with FTS5 and optional vector retrieval; a PostgreSQL plus Apache AGE backend is also documented. Records carry namespace, agent identity, typed memory and source/provenance fields. This is a bounded source review, not a runtime evaluation.[[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)] [[architecture limits](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/docs/ARCHITECTURAL_LIMITS.md)]

## Who and what

The repository identifies AlphaOne LLC in its source and security documentation. The project is a memory library/daemon with client-facing MCP, HTTP, and CLI surfaces; it is not itself an agent runtime. The root README describes persistent local memory and a PostgreSQL/Apache AGE option for multi-writer and graph workloads.[[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)] [[security policy](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/SECURITY.md)]

## Architecture and data model

A shared memory model is exposed through MCP tools, HTTP routes, and CLI commands. The project documents embedded SQLite and PostgreSQL plus Apache AGE storage backends. In the inspected model, a memory includes ID, tier, namespace, title, body, tags, priority, confidence, source role, access and time fields, expiration, metadata, typed kind, and optional citations, source URI, and source span. The model also carries identity/attestation, lifecycle, and derivation-related fields. Backend implementation parity and operational behavior were not exhaustively reviewed.[[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)] [[memory model](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/models/memory.rs)] [[SQLite migrations](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/storage/migrations.rs)] [[PostgreSQL schema](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/store/postgres_schema.sql)]

## Write, update, delete, and retrieval

**Writes.** The MCP `memory_store` request accepts title and content plus tier, namespace, tags, priority, confidence, source, metadata, agent identity, visibility scope, conflict policy, memory kind, citations, source URI, and source span. The handler is split into validation, transport, synthesis, legacy classification, and embedding stages. The README says HTTP direct writes require agent attestation by default at this revision; MCP and CLI are operator-as-actor paths and are permissive by default unless strict mode is configured. Thus a stored agent ID alone is not proof of identity.[[store handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/store/mod.rs)] [[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)] [[security policy](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/SECURITY.md)]

**Updates and correction.** `memory_update` accepts partial field changes by ID, supports an expected-version precondition, and documents edit-source behavior; the tool contract says omitted fields remain unchanged and tier updates are monotone-only. This review did not trace every update storage, versioning, and concurrent-conflict path. Versioning and timestamps exist in the model, but they do not by themselves establish correction accuracy.[[update handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/update.rs)] [[memory model](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/models/memory.rs)]

**Deletion.** `memory_delete` is documented as a hard delete by ID, removing the memory row and associated embedding, FTS entry, and links. A separate bulk forget path archives before deleting. The inspected delete handler records a governance decision and applies permissions before mutation. This review did not trace all replicas, backups, external exports, and backend cleanup paths, so complete erasure across every configured topology is unknown.[[delete handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/delete.rs)] [[forget handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/forget.rs)] [[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)]

**Retrieval.** `memory_recall` ranks memories for a context, with optional namespace, agent visibility, kinds, time and token-budget controls, archived-source selection, source/citation filters, and session-related boosts. The implementation can use FTS and HNSW candidates and exposes recall mode, reranker state, candidate counts, and blend telemetry in response metadata. `memory_search` is documented as deterministic exact-keyword AND search, distinct from fuzzy or semantic recall. The inspected SQLite recall comments note that tier filtering is not consumed on one legacy branch, while the PostgreSQL SAL handler applies it; callers should not assume identical behavior without checking the selected backend and route.[[recall handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/recall.rs)] [[search handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/search.rs)] [[recall request](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/models/recall_request.rs)]

## Scope isolation

Namespace is a first-class stored and retrieved filter. The MCP recall path can resolve caller visibility and apply private-row ownership checks; namespace ancestry and configured scope govern broader visibility. The README describes a recent hardening of team, unit, and organization scope resolution. The source also documents explicit trust assumptions: unsigned MCP or CLI writes may carry a claimed agent ID, and the curator daemon can operate across tenants as a privileged maintenance actor. These code and documentation observations do not prove isolation across every backend, route, plugin, federation peer, or deployment configuration; no cross-scope probes were run.[[recall handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/recall.rs)] [[visibility policy](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/visibility.rs)] [[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)] [[security policy](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/SECURITY.md)]

## Provenance and evidence

The model distinguishes a role-like `source` label from evidence pointers. It supports typed citations with URI, access time, optional hash and span; a `source_uri`; and a byte-range `source_span`. Agent identity and attestation fields also describe who made a write and its trust level. These fields improve traceability but do not establish that cited material supports a claim or that a caller-provided source is true. No citation-support adjudication was performed.[[memory model](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/models/memory.rs)] [[provenance guide](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/docs/provenance.md)] [[attestation guide](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/docs/attestation.md)]

## Source-visible efficiency and observability

The source shows optional vector search alongside indexed keyword search, filters applied to retrieval, response token-budget handling, and compact TOON serialization. Recall response metadata identifies retrieval mode, reranker selection, candidate counts, and blending; a separate observations surface records feedback about retrieved memories. The README reports historical LongMemEval measurements and compact-format size reductions, but these are upstream-published claims, not measurements from this review. No latency, throughput, token, cost, storage, or write-to-recall measurements were collected here.[[recall handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/recall.rs)] [[observations handler](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/mcp/tools/recall_observations.rs)] [[TOON implementation](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/src/toon.rs)] [[README](https://github.com/alphaonedev/ai-memory-mcp/blob/0f111b36908c8e5dbc7ff21a241aa497837cb4d0/README.md)]
