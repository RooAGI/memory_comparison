## Summary

Cyrene Agent is a Windows Electron/TypeScript desktop companion with a layered local memory store, hybrid vector/BM25 recall, DMAE prompt selection, and a separate optional social-context store keyed by conversation. This review covers selected current upstream source; no runtime, tests, or benchmarks were run.[[README](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/README.en.md)] [[memory types](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-types.ts)]

## Architecture and data model

Memory is organized as L0 core profile, L1 recent state, and L2 conversational memories, alongside the DMAE Worldbook. L0 contains profile fields such as preferred name, occupation, language and permanent notes; L1 contains recent goals, preferences and current project. L2 entries carry content, trigger text, source conversation, timestamps, access and weight state, pin/status, RAG sync identifiers and evidence references. The principal profile store is `memory.json` under Electron's user-data directory; RAG vectors are stored separately.[[README](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/README.en.md)] [[types](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-types.ts)] [[persistence](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-store-io.ts)]

The separate chat social-context subsystem stores long-term, short-term and open-loop atoms with conversation ID, status, expiry, evidence turn ID and quote. It is persisted separately from the profile/L2 memory store.[[social atom types](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/social-context/types.ts)] [[social service](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/services/social-context/social-context-service.ts)]

## Write, update, delete and retrieval

**Write.** Eligible conversation turns are queued for background judging in conversation-tagged batches. A judge extracts candidates; post-filters reject candidates marked not to write, overclaiming, or unsupported L0 writes. The manager writes L0 only from explicit user-attributed facts (and skips a pinned profile), replaces L1 fields, and creates L2 before synchronizing it to the vector index. Follow-on resolver, reflection/compression and decay maintenance run on periodic turn counts.[[scheduler](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-scheduler.ts)] [[judge](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-judge.ts)] [[manager](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-manager.ts)]

The `write_memory` tool exposes explicit writes to L0, L1 or L2; `read_memory` reads profiles and L2 entries directly. L0/L1 edits replace fields. The importer can edit L2 content, setting RAG sync pending until reindexed; conflict resolution records statuses and links between superseded/merged items. This source review did not find a generic in-place fact-correction path in the normal manager write flow.[[memory tools](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/orchestrator/tools/registry/tool-registry.ts)] [[store operations](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-store.ts)] [[conflict manager](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-manager.ts)]

**Delete.** The L2 store deletion removes the memory and its evidence rows from `memory.json`. That method does not itself remove the vector entry; separate RAG deletion and reconciliation functions handle vectors. Complete removal from all copies, backups or provider systems was not established.[[store deletion](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-store.ts)] [[RAG cleanup](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/rag/index.ts)]

**Retrieval.** User-memory recall first filters vector entries through a canonical L2 allowlist: only active/aging records with synced status and a matching RAG ID are eligible. Search combines vector and BM25 candidates with a 0.7/0.3 weight and may rerank the top results with a cross-encoder; without an embedding provider it falls back to BM25. DMAE separately chooses a bounded set of active L2 items for prompt injection. These are source-visible strategies, not evidence of answer quality.[[RAG index](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/rag/index.ts)] [[hybrid retriever](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/rag/retriever.ts)] [[DMAE selector](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/l2-dmae-manager.ts)] [[prompt injection](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/orchestrator/index.ts)]

## Scope isolation

The default L0/L1/L2 profile and user-memory retrieval are local to the desktop user's user-data store. L2 carries a `sourceConversationId`, but the inspected vector-recall allowlist does not filter on it; profile and selected L2 memories are shared across conversation contexts. Social atoms use a separate path: reads filter by `conversationId`, and extraction checks that mutation targets belong to that conversation. No cross-conversation or cross-user probes were run.[[types](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-types.ts)] [[RAG index](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/rag/index.ts)] [[social store](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/social-context/store.ts)] [[social extraction](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/social-context/extractor.ts)] [[runtime integration](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/orchestrator/agent-runtime.ts)]

## Provenance and evidence

L2 records link to evidence rows containing a bounded quote snippet, conversation and optional message IDs, timestamp and source status. Current code creates the quote from trigger text (or memory content); the store itself does not verify that it is a literal span of the original transcript. The social-context extractor does enforce a stricter rule: evidence quotes must be exact substrings of the referenced turn, and turn role and conversation are validated before accepting add, supersede or resolve operations. An audit helper can flag missing evidence links, overclaims, stale sync, unresolved conflict markers and broken resolution links.[[memory evidence model](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-types.ts)] [[store evidence creation](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-store.ts)] [[social extraction](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/social-context/extractor.ts)] [[memory audit](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-audit.ts)]

## Efficiency and observability

The implementation uses local JSON persistence, cached tokenization, hybrid retrieval, optional reranking and queued maintenance. Memory traces append operation names, status and IDs to `memory-trace.log`; trace-write failures only emit a warning. Social extraction logs accepted/rejected counts and retries/repairs. These are implementation-level observability signals; no latency, token, cost or storage measurements were collected.[[persistence](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-store-io.ts)] [[retriever](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/rag/retriever.ts)] [[trace](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/memory/memory-trace.ts)] [[social service](https://github.com/Playa-Cyrene/Cyrene-Agent/blob/f6d8a5edce2b1ae3847a69022f880c49c221dc50/src/main/services/social-context/social-context-service.ts)]
