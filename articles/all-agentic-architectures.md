## Summary

This repository is a Python library and runnable textbook for many agent architectures. Its memory-related patterns include episodic plus semantic memory, graph memory, MemGPT-style tiered memory, Voyager skills, Reflexion episodes, and workflow recipes. They share some helper modules but are not one memory service or one uniform persisted data model. The review below focuses on the shared vector and graph abstractions and selected memory patterns.[[README](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/README.md)] [[memory source directory](https://github.com/FareedKhan-dev/all-agentic-architectures/tree/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory)]

## Architecture and data model

The dual-memory pattern stores timestamped episodes—content, role, timestamp, and metadata—in a vector-backed `EpisodicMemory`, alongside semantic facts represented as subject-predicate-object triples. `SemanticMemory` delegates to a graph abstraction. The graph defaults to an in-process NetworkX `MultiDiGraph` or can use Neo4j; vector configuration supports in-memory, FAISS, Chroma, and Qdrant stores.[[episode model and store](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/episodic.py)] [[semantic wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/semantic.py)] [[graph backends](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/graph.py)] [[vector backends](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/vector.py)]

Other patterns have different lifecycles. MemGPT keeps a bounded context list and sends evicted or explicitly written text to a vector archive. Agent Workflow Memory extracts recipe steps, stores them in an in-process list, and adds a text representation to a vector index. This variation means persistence and lifecycle depend on the chosen architecture and backend.[[MemGPT](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/memgpt.py)] [[Agent Workflow Memory](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/agent_workflow_memory.py)]

## Write, update, delete, and retrieval

**Writes.** `EpisodicMemory.record` appends an episode to its local list and writes a LangChain document to the vector store. In `EpisodicSemanticAgent.run`, retrieval precedes answer generation; the agent then extracts structured triples from the interaction, adds those facts, and stores the Q&A as an episode. `GraphMemoryAgent.ingest` separately extracts triples from supplied text and adds them to semantic memory.[[episodic store](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/episodic.py)] [[dual-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/episodic_semantic.py)] [[graph-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/graph_memory.py)]

**Updates and deletion.** The inspected episodic and semantic wrappers expose no item-level update or delete API. `SemanticMemory.reset` clears its graph; the selected vector and episodic wrappers do not expose a reset or delete method. MemGPT archives context items evicted by FIFO but the inspected architecture has no targeted forget path. Backend-specific deletion capabilities are outside this wrapper-level finding.[[episodic store](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/episodic.py)] [[semantic wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/semantic.py)] [[vector wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/vector.py)] [[MemGPT](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/memgpt.py)]

**Retrieval.** Episodic recall delegates to vector similarity search with a configurable `k`. The dual-memory agent also matches entity names as substrings in NetworkX nodes, falls back to up to ten entities for short generic queries, then gets graph facts to a configured depth. Graph Memory matches entities in the query, falls back to up to twenty graph entities for short questions, traverses facts, and prompts the model to answer from them. AWM retrieves one similar recipe; MemGPT has the model choose whether to write to, search, or answer from archival memory within a bounded action loop.[[vector wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/vector.py)] [[dual-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/episodic_semantic.py)] [[graph-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/graph_memory.py)] [[AWM](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/agent_workflow_memory.py)] [[MemGPT](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/memgpt.py)]

## Scope isolation

The selected episode and triple models do not require tenant, user, project, or agent ownership fields. Their wrappers accept no scope filter. AWM tags recipes with task type, but this is a retrieval label, not an access-control boundary. A host may add isolation around a configured database, but that was not established by the selected code.[[episode model](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/episodic.py)] [[semantic wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/semantic.py)] [[vector wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/vector.py)] [[AWM](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/agent_workflow_memory.py)]

## Provenance and evidence

Episodes have timestamps, roles, and free-form metadata. Semantic memory exposes triples through its wrapper. The dual-memory architecture trace includes recalled episode excerpts, retrieved facts, the response, and newly extracted facts. Graph Memory prompts the model to cite triples in its response, but the selected retrieval APIs do not enforce claim-level citations or retain original source documents with each fact.[[episode model](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/episodic.py)] [[semantic wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/semantic.py)] [[dual-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/episodic_semantic.py)] [[graph-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/graph_memory.py)]

## Source-visible efficiency and observability

The vector abstraction accepts a top-k bound and delegates retrieval to the configured backend. NetworkX is an in-process graph implementation with a small Cypher subset; source comments recommend Neo4j for full Cypher support and larger workloads. The architecture results carry traces and counts such as recalled episodes/facts, graph entities/backend, workflow library size, and MemGPT action history. These source-visible controls and traces do not provide measured latency, resource use, storage, or cost.[[vector wrapper](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/vector.py)] [[graph backend](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/graph.py)] [[dual-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/episodic_semantic.py)] [[graph-memory agent](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/graph_memory.py)] [[AWM](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/agent_workflow_memory.py)] [[MemGPT](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/architectures/memgpt.py)]

## Limits and unknowns

This is a bounded inspection of the README and selected memory abstractions and architectures at one verified commit. It does not cover every architecture, backend adapter, notebook, or deployment setup. No system execution, tests, or benchmarks were run. The default NetworkX graph and in-memory vector backend are process-local; any durable behavior depends on configuration and the host. Runtime quality, complete erasure, isolation under a deployment, and operational performance remain unknown from this source review.[[README](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/README.md)] [[graph backend](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/graph.py)] [[vector backend](https://github.com/FareedKhan-dev/all-agentic-architectures/blob/e82faf3e211995d91738af5f39d6efd26045e435/src/agentic_architectures/memory/vector.py)]
