## Architecture and data model

CrewAI is a Python agent and workflow framework. Its unified `Memory` API can be used standalone or with Crews, Agents, and Flows. A Crew may share one memory instance among its agents; an agent may receive a separate instance or scoped view. Memory is optional and must be enabled or supplied by the application.[[memory guide](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/docs/v1.15.45/en/concepts/memory.mdx)] [[crew integration](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/crew.py)]

A `MemoryRecord` has a generated ID, text content, hierarchical scope path, categories, arbitrary metadata, importance from 0 to 1, creation and last-access timestamps, an optional embedding, free-form source string, and a private flag. Results wrap a record with a composite score, match reasons, and optional evidence-gap text. These fields are a record model, not an enforced claim/evidence graph.[[memory types](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/types.py)]

The built-in storage choices are LanceDB by default and Qdrant Edge, with a storage protocol for custom backends. The default embedding provider is OpenAI unless configured otherwise. The official guide documents a local default storage directory and warns that existing stores can be incompatible after embedding dimension changes. The documentation and source expose storage and embedder selection; this review does not validate deployment or provider behavior.[[unified Memory](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/unified_memory.py)] [[storage protocol](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/storage/backend.py)] [[memory guide](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/docs/v1.15.45/en/concepts/memory.mdx)]

## Write, update, delete, and retrieval

**Write.** `remember()` sends a synchronous save through a serialized save pool. `remember_many()` queues work in a background thread; later recall waits for pending saves. The encoding flow embeds a batch, drops near-duplicate items within that batch, searches for similar existing records, resolves missing scope/categories/importance/metadata with LLM analysis, and asks an LLM for consolidation actions when the similarity threshold is met. It then applies record updates/deletions and bulk inserts. Analysis failures fall back to storing new content, but a successful consolidation plan can update or delete existing records without a human review step in this path.[[unified Memory](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/unified_memory.py)] [[encoding flow](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/encoding_flow.py)] [[analysis and consolidation](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/analyze.py)]

**Update and correction.** The explicit `update(record_id, ...)` path fetches a record by ID, replaces selected fields, recomputes an embedding if content changes, and writes the replacement under the same ID. The inspected record schema has no revision history or prior-value ledger. LLM-driven consolidation can also replace content or delete similar entries. These are available mutation mechanisms; correction accuracy and stale-value handling are not established by source inspection.[[unified Memory](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/unified_memory.py)] [[encoding flow](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/encoding_flow.py)]

**Delete.** `forget()` deletes records matching optional scope, categories, age, metadata, and/or IDs. `reset()` deletes a scope or the full store; `reset_all()` explicitly ignores the instance root scope. The built-in stores implement deletion operations, but no system was run and no physical-erasure or post-delete retrieval check was performed.[[unified Memory](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/unified_memory.py)] [[LanceDB storage](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/storage/lancedb_storage.py)] [[Qdrant Edge storage](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/storage/qdrant_edge_storage.py)]

**Retrieval.** Shallow recall embeds the query and performs one vector search, then re-ranks using semantic similarity, recency decay, and importance. Deep recall is the default: it may distill longer queries into subqueries, selects candidate scopes, searches query/scope pairs in parallel, and can spend a bounded exploration round when confidence is low. Results expose match reasons; exploration may attach short text describing missing information as evidence gaps. This is not an answer-level citation or abstention guarantee. The documented query-length shortcut and scoring defaults are configuration behavior, not measured quality claims.[[unified Memory](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/unified_memory.py)] [[recall flow](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/recall_flow.py)] [[memory types](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/types.py)]

## Scope isolation

Scopes are hierarchical path prefixes, with optional instance or per-call root scopes and `MemoryScope`/`MemorySlice` views. Records also carry a `source` and `private` flag; private records are filtered by matching source unless the caller requests `include_private`. These are caller-provided data and query parameters, not an authenticated principal or tenant policy. Crew agents sharing a backing memory can therefore see records in scopes their application exposes. In the inspected LanceDB backend, scope filtering uses a string-prefix `LIKE` predicate; Qdrant Edge instead matches stored ancestor paths. Neither code path establishes authorization by itself.[[memory scope](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/memory_scope.py)] [[LanceDB storage](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/storage/lancedb_storage.py)] [[Qdrant Edge storage](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/storage/qdrant_edge_storage.py)] [[memory guide](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/docs/v1.15.45/en/concepts/memory.mdx)]

## Provenance, efficiency, and observability

The source field is a free-form string (the API examples suggest user or session identifiers); metadata and categories are arbitrary caller or LLM-derived values. They can describe origin, but the schema does not require source-document IDs, immutable evidence, trust state, or a verification chain. Recall’s `evidence_gaps` is generated query-gap text, not a link from answer claims to source passages.[[memory types](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/types.py)] [[analysis](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/analyze.py)] [[recall flow](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/recall_flow.py)]

The source uses batch embedding, within-batch cosine deduplication, parallel similarity lookup and parallel LLM analysis; recall can parallelize up to four query/scope searches and oversamples candidates before composite scoring. Memory emits start, completion, and failure events for saves and queries, including elapsed-time fields on successful operations. Events can carry query, content, metadata, or returned results; applications should account for that when wiring listeners. These are implementation observations, not throughput, latency, or cost measurements.[[encoding flow](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/encoding_flow.py)] [[recall flow](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/recall_flow.py)] [[memory events](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/events/types/memory_events.py)]

## Limits and unknowns

This bounded review covered the official README and memory guide, record/config types, unified Memory API, encoding and recall flows, consolidation analysis, both built-in storage backends, scope views, and memory events. It did not trace every integration, migration, custom backend, or error path. Source inspection cannot establish actual retrieval quality, correction correctness, security of an application’s scope policy, deletion guarantees, operational reliability, or the resource profile at scale.[[README](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/README.md)] [[memory guide](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/docs/v1.15.45/en/concepts/memory.mdx)] [[unified Memory](https://github.com/crewAIInc/crewAI/blob/ba2bd50f70069e3079eed29bb9cbed3f777c548b/lib/crewai/src/crewai/memory/unified_memory.py)]
