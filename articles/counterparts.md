## Summary and architecture

Counterparts is a local-first TypeScript memory system for Claude Code and Claude Desktop. It provides host hooks, an MCP server, CLI, dashboard and background worker. The README describes the model writing selected memories in its own words, plus a first-person session journal, instead of keeping transcripts as its main memory representation.[[README](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/README.md)] [[remember contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/remember/CONTRACT.md)]

The current store contract defines SQLite counterparts.sqlite as canonical for memory text and structured state. Memory title, body, metadata and content hash live on a row; Markdown is a one-way export and journal files are derived copies. A separate cache stores full-text and vector indexes and is rebuildable, while daily snapshots cover the canonical database.[[store contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/CONTRACT.md)] [[store implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/index.ts)]

Memory records include stable IDs, type/kind, text, metadata, provenance, happened/learned dates, salience, lifecycle and lived-day use/decay state. Related structures represent versions, entities and beliefs, contradictions, associations, reminders, session gates and operational events.[[store shapes](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/shapes.ts)] [[schemas contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/schemas/CONTRACT.md)]

## Write, update, delete, and retrieval

**Write.** The documented primary flow asks the model to write selected memories during or at the end of a session. The encode pipeline applies credential scanning and proposal gates before durable storage. Store writes are transactional. Crash fallback and later catch-up paths can process captured session material.[[README](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/README.md)] [[remember contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/remember/CONTRACT.md)] [[encoding contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/encode/CONTRACT.md)] [[store implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/index.ts)]

**Update and correction.** A revision writes the prior words, metadata and provenance dates to a version row in the same transaction as the new version. Supersession creates a successor ID, retains the predecessor and a forwarding relationship, and removes the old item from live search. Beliefs and contradictions have separate change-state machinery. These structures preserve history but do not show that a proposed correction is true.[[store contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/CONTRACT.md)] [[store implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/index.ts)] [[update implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/remember/updates.ts)] [[schemas contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/schemas/CONTRACT.md)]

**Delete and retention.** Nightly lifecycle rules fade, archive, prune and consolidate eligible memories. Archival is a state change, not erasure. Permanent removal uses a distinct owner-facing CLI path: it plans and asks for confirmation, records the request, denies the ID to readers, then chases known related content and dependent rows. The reviewed store seam removes body text and versions, association links, reminders, feelings and related state while retaining a stripped lineage skeleton and content-free removal record. The CLI identifies surfaces it leaves or cannot chase.[[sleep contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/sleep/CONTRACT.md)] [[pruning implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/sleep/prune.ts)] [[removal workflow](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/adapters/cli/removal.ts)] [[removal seam](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/owner-op-seam.ts)]

**Retrieval.** Hook-driven recall derives weighted cues from the current turn and can combine rarity-weighted lexical matches, local semantic vectors, context/time cues and bounded spreading activation over associative links. Candidate eligibility and lived-day physics affect activation. Memories can surface quietly or be retrieved through deliberate recall/ask tools; start-of-session briefings and prospective reminders provide additional context.[[README](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/README.md)] [[recall contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/recall/CONTRACT.md)] [[activation implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/recall/activate.ts)] [[association contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/associate/CONTRACT.md)]

## Scope isolation

The store is local to a user installation rather than one database per project. The README says personal memories may reach every folder and project-work memories appear in their project. A separate scopes.json registry sits beside host configuration; paths are canonicalized, longest segment-aware prefix wins, and modes include on, observer, off and paused.[[README](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/README.md)] [[scope registry](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/adapters/scopes.ts)]

This is host-level directory behavior, not tenant authorization inside a shared hosted database. The reviewed local design relies on the local account, host configuration and correct folder/session selection for isolation.[[scope registry](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/adapters/scopes.ts)] [[store contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/CONTRACT.md)]

## Provenance and evidence

Memory inputs can record source and origin references such as session, scope, reference ID and span hash. The store distinguishes when an event happened from when it was learned; revisions preserve earlier words and dates. Entity/belief records, contradiction state, supporting references and operational events add lineage and change context.[[store shapes](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/shapes.ts)] [[store implementation](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/index.ts)] [[schemas contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/schemas/CONTRACT.md)]

The store contract says operational telemetry carries identifiers, hashes, counts and kinds instead of body text. Removal records are content-free by design. These mechanisms preserve some lineage but do not guarantee claim-level citations in every answer or that model-authored memory is factually correct.[[store contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/CONTRACT.md)] [[removal seam](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/owner-op-seam.ts)] [[remember contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/remember/CONTRACT.md)]

## Efficiency and observability

Canonical content and structured state use local SQLite; full-text and vector search use a separate cache. The README describes the semantic model as a small local model of about 30 MB, but this review did not measure resources. Recall cue processing, associative spreading and nightly work have explicit bounds or phases. Dashboard, doctor/status commands and event records provide operational visibility.[[README](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/README.md)] [[store contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/CONTRACT.md)] [[recall contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/recall/CONTRACT.md)] [[association contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/associate/CONTRACT.md)] [[sleep contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/sleep/CONTRACT.md)]

## Limitations and unknowns

The README calls Counterparts early. At the reviewed revision it reports Node and Linux pass smoke and install checks but do not yet have a daily user. Its own description says semantic search finds close paraphrases but may miss an indirect description that never names the subject. Credential scanning is shape-based and the README warns that not every secret has a recognizable form.[[README](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/README.md)] [[encoding contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/encode/CONTRACT.md)]

Archival, pruning and permanent removal are separate lifecycle actions. The reviewed removal workflow reports known unchased or deliberately retained surfaces; this review does not establish erasure from arbitrary external copies, backups, host transcripts or user-created exports.[[sleep contract](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/sleep/CONTRACT.md)] [[removal workflow](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/adapters/cli/removal.ts)] [[removal seam](https://github.com/mlapeter/counterparts/blob/d5a7168485a216f194c389f4f3dbba2a12e79764/src/core/store/owner-op-seam.ts)]
