## Summary

ArcRift is a local-first AI memory application combining a browser extension, desktop dashboard, backend, and MCP server. It stores conversations and extracted graph facts by project/session, then retrieves vector, keyword, and graph context for browser prompts or coding agents. This is a pinned source review; this task did not run ArcRift or its benchmarks.[[readme](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/README.md)] [[architecture](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/ARCHITECTURE.md)]

## Who and what

The README credits the project as built by Eshaan Nair. ArcRift is a self-hostable application/framework for end users and coding agents: the extension captures browser conversations, while an MCP server exposes memory tools to supported coding clients. The README describes local Ollama models as the primary embedding and extraction path, with an optional Groq fallback.[[readme](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/README.md)] [[security](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/SECURITY.md)]

## Architecture and data model

The documented architecture has a browser extension, a Tauri/React desktop interface, and a Node.js backend that also provides the MCP stdio server. Storage is selected as SQLite/SQLite-vec or a Docker profile using MongoDB, Neo4j, and ChromaDB. The README and architecture guide describe the same memory surface across the extension and MCP interface.[[architecture](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/ARCHITECTURE.md)] [[storage](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/storage.ts)]

The inspected SQLite schema stores project sessions, full chats, background jobs, extracted facts, chunk metadata, sentence metadata, vector tables, and an FTS5 index. A fact is a subject–relation–object record with types, session ID, and timestamp. Chunk metadata includes session ID, chunk index, text, and optional file path/hash; vector tables use 768-dimensional embeddings.[[sqlite](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite.ts)] [[graph](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-graph.ts)] [[vector](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-vector.ts)]

The source has distinct ingestion paths. Browser chat save scrubs PII and queues a \`chat_ingestion\` job; the MCP \`store_memory\` tool saves full chat, attempts graph extraction, chunks text, stores vectors, and updates session statistics. The MCP path uses 150-word windows with 50-word overlap, while the architecture guide documents 300-word windows with 80-word overlap for browser chat ingestion; these are path-specific configurations, not a single universal setting.[[chat route](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/routes/chat.ts)] [[store tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/store.ts)] [[architecture](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/ARCHITECTURE.md)]

## Write, update, delete, and retrieval

**Write.** Browser chat save validates required fields, session identifier format, and a 50-character minimum, scrubs PII, then enqueues ingestion and returns a job ID. MCP \`store_memory\` finds a session by ID or name and creates one if absent, saves the full chat, extracts graph triples on a best-effort basis, stores chunk vectors, and increments the session triple count. A graph extraction failure is swallowed so the vector path can continue.[[chat route](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/routes/chat.ts)] [[store tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/store.ts)]

**Update and correction.** Saving full chat again upserts the session's full-chat row. Vector storage uses replace semantics for chunk IDs, while the docs describe delete-then-insert for refreshed vector rows. The inspected MCP API does not expose a general fact-edit/version-history operation: \`prune_memory\` removes matched material, after which new content can be stored. The coverage and correctness of that correction workflow were not measured.[[session store](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-session.ts)] [[vector store](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-vector.ts)] [[prune tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/prune.ts)]

**Delete and prune.** MCP pruning extracts entities from the request, deletes graph triples for the selected session, and deletes vector chunks whose stored text contains the request substring. If extraction fails, it falls back to words longer than four characters. SQLite session deletion removes vector rows before deleting the session, whose foreign-key cascades cover metadata, facts, and full chats. The inspected HTTP chat DELETE route only calls vector deletion and returns success; its own comment notes that session-store deletion may be needed in Docker mode. The review did not establish cleanup of backups, exports, or other copies across every mode.[[prune tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/prune.ts)] [[session store](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-session.ts)] [[chat route](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/routes/chat.ts)]

**Retrieval.** MCP \`recall_context\` looks up a session, extracts query entities, retrieves up to 15 related graph triples for that session, and requests top-N vector chunks. It sanitizes retrieved chunks before formatting structured facts and context; optional debug output names the retrieval engines. The SQLite vector implementation combines sentence-vector, chunk-vector, and FTS candidates, applies a 0.30 session threshold, trims results to matching sentences (with a short fallback for history queries), ranks, and caps the result count. The browser extension path is documented as a hybrid retrieval flow; global search is an explicit cross-project path.[[recall tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/recall.ts)] [[vector store](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-vector.ts)] [[RAG guide](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/RAG_PIPELINE.md)]

**Scope isolation.** Session IDs are carried by graph facts and chunk metadata; scoped recall and pruning query by that session ID. The README documents global search across projects, and the architecture guide describes project/session constraints. This is a project/session boundary rather than a user or organization identity boundary. I did not inspect an authorization layer proving that a caller may access only its assigned session, and no isolation probe was run. The MCP store tool accepts a project name fallback while recall directly looks up a session ID, so the precise caller contract should be checked against deployed integration behavior.[[store tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/store.ts)] [[recall tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/recall.ts)] [[graph](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-graph.ts)] [[architecture](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/ARCHITECTURE.md)]

**Provenance and evidence.** Full chat rows retain raw text, platform, message count, and timestamps. Extracted facts carry subject/object types, relation, session ID, and timestamp; vector chunks carry IDs, session, index, text, and optional source path/hash. Recall can expose engine names in debug output, but the inspected fact response does not attach source-span citations to claims. These fields support traceability to stored sessions/chunks but do not establish truth, extraction accuracy, or citation support.[[sqlite](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite.ts)] [[graph](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-graph.ts)] [[vector](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/sqlite-vector.ts)] [[recall tool](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/mcp/tools/recall.ts)]

## Limits and unknowns

This is a bounded inspection of selected documentation and implementation files at the reviewed SHA. It does not establish runtime retrieval quality, prompt-injection resistance, deletion completeness, cross-project authorization, or performance. The README and architecture guide describe multiple adapters, but this review inspected the SQLite implementations and interface selection, not the full behavior of MongoDB, Neo4j, and ChromaDB backends. Storage-mode differences and configuration-dependent behavior remain unknown beyond the cited paths.[[storage](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/backend/src/services/storage.ts)] [[security](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/SECURITY.md)]

The project README reports benchmark numbers and an isolation audit, but those are upstream project-reported results, not measurements from this review. This review did not reproduce or adjudicate them. In particular, source structure and documented thresholds cannot establish that relevance filtering, graph extraction, or tenant isolation meet a quality target.[[readme](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/README.md)] [[benchmark guide](https://github.com/Eshaan-Nair/ArcRift/blob/5424ea14dd9a848dcbcfb49586f348324999af88/BENCHMARKS.md)]
