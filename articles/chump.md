## Summary

Chump's built-in agent stores semantic memories in SQLite with FTS5, optional local embeddings, and an associative relation graph; it also records episodic events. This review describes inspected source paths only; no Chump workload or benchmark was run.[[README](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/README.md)] [[memory implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[graph implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_graph.rs)]

## Who and what

The official repository describes Chump as both an agent fleet coordinator and an optional self-hosted coding agent. This assessment focuses on durable memory inside the built-in agent: semantic memory, an associative graph, and episodic logs.[[README](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/README.md)] [[architecture](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/docs/architecture/ARCHITECTURE.md)]

## Architecture and data model

The memory subsystem stores semantic entries in SQLite at `sessions/chump_memory.db` when the pooled database is available, with a JSON fallback at `sessions/chump_memory.json`. SQLite rows contain content, timestamp, source, confidence, verified flag, sensitivity, optional expiry, and memory type; an FTS5 external-content index is maintained by insert, update, and delete triggers. Embeddings are stored in a separate JSON sidecar. The associative graph stores subject-relation-object triples with optional source memory or episode IDs and weights. Episodic events use a separate table in the same database.[[memory implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[SQLite schema](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-memory-db/src/memory_db.rs)] [[graph implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_graph.rs)] [[episode store](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/episode_db.rs)] [[database pool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-db-pool/src/lib.rs)]

The core memory tool, MCP memory server, and episode store are separate interfaces to local persistence. The MCP documentation describes a repo-root-based DB path and optional `CHUMP_MEMORY_DB` override. The core memory tool's JSON and embedding paths are relative to its process working directory. The inspected records do not contain user or tenant identity.[[MCP README](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/README.md)] [[MCP implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/src/main.rs)] [[memory implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)]

## Write, update, delete, and retrieval

**Write — code observation.** The core tool accepts store content and optional confidence, memory type, and expiry duration. It truncates stored text at 500 characters and records source and timestamp, then attempts to create an embedding and extract simple relation triples. It writes to JSON if SQLite is unavailable. Episode logging separately stores summary, detail, tags, repo, sentiment, and optional PR or issue numbers. The MCP server exposes memory search/recall and episode save/search operations.[[memory tool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[SQLite store](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-memory-db/src/memory_db.rs)] [[graph extraction](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_graph.rs)] [[episode store](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/episode_db.rs)] [[MCP implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/src/main.rs)]

**Update and correction — code observation.** The inspected core memory tool offers store and recall, but no general item edit or user-facing forget action. Maintenance code expires rows, removes exact duplicates, lowers confidence on unverified entries, and can summarize older episodes. These paths do not provide correction history or establish updates to all derived data.[[memory tool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[SQLite maintenance](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-memory-db/src/memory_db.rs)]

**Delete — code observation.** Expiry and deduplication delete semantic rows; FTS triggers keep the text index synchronized. I found no direct per-item delete interface in the inspected memory APIs. Graph triples can retain a source memory ID, but synchronized graph cleanup on expiry/deletion was not established. The embedding sidecar, JSON fallback, and backups are also outside the demonstrated row deletion path.[[SQLite maintenance](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-memory-db/src/memory_db.rs)] [[graph implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_graph.rs)] [[memory tool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[MCP implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/src/main.rs)]

**Retrieval — code observation.** The internal hybrid path may combine FTS keyword candidates, cosine similarity over local embeddings, and graph-associated memory IDs with reciprocal-rank fusion. It can then apply optional BM25 reranking and an MMR diversity pass, caps returned context, and falls back to keyword search when embedding is unavailable. A separate basic recall action uses keyword search; MCP uses FTS5 and LIKE. These source paths do not establish retrieval accuracy, and the MCP docs' relevance wording is not a measured result.[[memory tool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[SQLite retrieval](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-memory-db/src/memory_db.rs)] [[graph retrieval](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_graph.rs)] [[MCP implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/src/main.rs)] [[MCP README](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/README.md)]

**Scope isolation — code observation.** Memory paths are rooted in the process repository or configured `CHUMP_REPO`/`CHUMP_HOME`; the MCP README describes a separate DB per repo by default. Episode queries optionally filter by repo, but without a filter search the shared episode table. I found no per-user authorization layer or cross-scope isolation test in the inspected paths. Repository-local paths alone do not establish isolation for multi-user hosts.[[MCP README](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/README.md)] [[MCP implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/mcp-servers/chump-mcp-memory/src/main.rs)] [[episode store](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/episode_db.rs)] [[database pool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-db-pool/src/lib.rs)]

**Provenance and evidence — code observation.** Semantic rows retain a source string and timestamp; graph triples can point to source memory or episode IDs; episodes retain repo, PR, and issue metadata. The memory source is a source hint (including a Discord channel identifier in that constructor). The inspected schema does not require a source URL, quote, claim-level citation, or evidence validation. These fields help trace origin but do not establish evidence support.[[SQLite schema](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/crates/chump-memory-db/src/memory_db.rs)] [[memory tool](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_tool.rs)] [[graph implementation](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/memory_graph.rs)] [[episode store](https://github.com/repairman29/chump/blob/6b818800cd6eca1b7fe9c759584c53b215265719/src/episode_db.rs)]
