GitLord is a Python agent-orchestration framework that treats conversation turns and tool events as versioned Git commits. The repository describes a separate log repository for agent history and workspace repository for files, with session and subagent branches. Its package includes session, Git plumbing, subagent, context assembly, MCP, model routing, JSON query/index, and optional Chroma vector-index modules.[[README.md](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/README.md)] [[architecture documentation](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/docs/architecture.md)]

## Architecture and data model

**Documentation and code observation.** GitLord writes its log repository with Git plumbing: serialize a turn JSON blob, insert it under a zero-padded `turns/` filename in a tree, make a commit, then compare-and-swap the session ref. Each session branch is under `refs/agents/<session-id>`; subagents use nested refs under `refs/agents/sub/`. The separate workspace repository is cross-referenced by a `workspace_commit` SHA stored on the turn, rather than merged into the log repository.[[architecture documentation](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/docs/architecture.md)] [[Git plumbing and commit records](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/git.py)] [[session lifecycle](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/session.py)]

A `Turn` record has a turn number, role, timestamp, agent and parent-agent IDs, content, optional tool inputs/outputs, model, token counts, cost, error, workspace commit, tags, and summary references. Git commit trailers repeat searchable metadata such as role, agent, tokens, cost, errors, tool calls, parent SHA, and subagent result. These fields describe execution events; the inspected schema has no structured belief confidence, claim-verification, or source-citation fields.[[turn and trailer schemas](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/schemas.py)] [[Git commit records](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/git.py)]

## Write, update, delete, and retrieval

**Write — code observation.** Session creation makes an orphan branch and records an initial system turn. Appending a turn captures the current workspace HEAD, assigns the next turn number, builds a Git commit, and updates the branch ref with compare-and-swap retry logic. With automatic indexing enabled, the append path rebuilds the JSON index after the commit.[[session lifecycle](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/session.py)] [[Git commit and ref update](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/git.py)] [[session and turn schema](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/schemas.py)]

**Update and delete — code observation.** The inspected session API appends turns and can rewind by creating a new branch at an earlier commit; it does not edit or remove an individual turn from the history. Subagent completion records the result in the parent and, unless configured to retain subagent branches, deletes the subagent ref. Trimming also deletes eligible refs. Removing a ref does not itself demonstrate that underlying Git objects are physically erased; no permanent-erasure or retention test was run.[[session lifecycle](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/session.py)] [[subagent completion and trim](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/subagent.py)]

**Retrieval — documentation and code observation.** `Session.get_turns` walks the current branch history and can restrict results by turn-number range. The JSON `IndexBuilder` walks agent refs and builds a materialized index with turn SHA, session, role, tags, tool, agent, tokens, cost, and error metadata. `TurnQuery` filters and aggregates those loaded records. The optional `VectorIndex` stores chunked turn text with SHA, agent ID, turn, tags, and timestamp metadata; its query accepts an optional metadata filter, and its MMR API is a separate retrieval path. The README presents semantic search as an optional capability; the code inspection does not establish a single automatically invoked retrieval policy for every agent call.[[session retrieval](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/session.py)] [[JSON index rebuild](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/index.py)] [[query and aggregations](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/query.py)] [[optional vector index](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/rag.py)]

## Scope isolation, provenance, and evidence

**Scope observation.** A session's commit history and context assembly take a specific branch, and subagents have separate branches. However, the rebuilt JSON index groups all discovered agent refs under sessions, `TurnQuery` loads every session in the index, and `Session.query()` loads that file without adding a session filter. The optional vector index carries agent metadata and supports caller-supplied filters, but the inspected source does not show mandatory tenant or user authorization enforcement. Branch separation is a storage organization mechanism, not evidence of an access-control boundary; no cross-session or cross-user probes were run.[[session query](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/session.py)] [[JSON index rebuild](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/index.py)] [[query loading and filtering](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/query.py)] [[vector metadata filters](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/rag.py)]

**Provenance and evidence.** Git commit IDs provide stable event identity and ancestry; turn fields and commit trailers can preserve timestamp, agent, parent, tool, model, workspace SHA, tokens, cost, errors, and subagent-result SHA. This is useful execution provenance and supports inspection or branching. It does not by itself represent whether a factual claim is trusted or attach evidence citations to claims.[[turn and trailer schemas](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/schemas.py)] [[Git commit records](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/git.py)]

## Efficiency and observability

**Source-visible design.** Log writes use Git plumbing without checking out a working tree. Context assembly can cache branch-and-turn results, substitute summaries, deduplicate repeated file reads using content hashes, prepend supplied RAG results, and enforce a token budget. Git metadata and the JSON query layer expose turn/token/cost/error fields and aggregate operations. The automatic JSON index rebuild scans refs and branch commits after writes; the session wrapper suppresses exceptions from that rebuild. These are implementation observations, not measured throughput, cost, or reliability results.[[architecture documentation](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/docs/architecture.md)] [[context assembly](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/context.py)] [[session index rebuild](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/session.py)] [[index builder](https://github.com/yashneil75/gitlord/blob/8bfe0aa391a82cf62e595cd41bba06c7e4966e39/gitlord/index.py)]
