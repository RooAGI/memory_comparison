## Summary

Empryo is an agent coding harness whose public SoulForge v2 core includes persistent cross-session memory. The inspected subsystem stores categorized memories in project and global SQLite databases and combines lexical, semantic, file, and usage signals for recall. It supports updates, restorable soft deletion, and supersession. The repository says the public source is not the full current Empryo v3 source, and this review makes no runtime or performance claims.

## Who and what

The official [README](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/README.md) describes Empryo as a coding harness with desktop, terminal, and headless modes. It says this repository contains the public SoulForge v2 core and engine, not the full source of Empryo v3. The inspected core includes an agent memory tool and a `/memory` browser. The README publishes **empryo@proxysoul.com** as the commercial licensing contact; the checked official source is the pinned README.

## Architecture and data model

The [manager](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/manager.ts) opens separate SQLite databases at `.soulforge/memory.db` per project and `~/.soulforge/memory.db` globally. Each [memory record](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/types.ts) stores category, summary, details, topics, source (user or agent), session ID, timestamps, use count, content hash, pin/hidden state, and optional supersession. File references are stored separately.[[database](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/db.ts)]

SQLite FTS5 provides a Unicode word index and a trigram index. Embeddings are stored with the records and can be generated by the built-in hashbag-v2 embedder or a configured provider; the offline embedder uses normalized 384-dimensional vectors. Similarity and supersession relationships are represented by memory edges.[[database](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/db.ts)] [[embedder](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/embedder.ts)]

Recall combines lexical ranks, semantic similarity, recency, use count, pinning, direct file matches, git co-change affinity, and code blast radius. It applies a score threshold, result limit, and character budget. The memory documentation describes silent injection of up to three relevant memories before a turn; no retrieval result quality was measured.[[recall](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/recall.ts)] [[memory documentation](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/mintlify-docs/tools/memory.mdx)]

## Write, update, delete, and retrieval

**Write and update.** The [memory tool](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/tools/memory.ts) exposes write, search, list, get, delete, restore, pin, unpin, and supersede actions. Writes deduplicate on a hash of summary/details; an explicit ID can upsert an existing record. Identical content can refresh use metadata and can unhide a hidden row. Similarity hints are advisory. This supports updates, but the inspected record schema does not provide a separate version history.[[database](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/db.ts)] [[record types](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/types.ts)]

**Delete.** Delete marks the row hidden and removes its similarity edges. Restore makes it visible again and attempts to rebuild its similarity links. Supersede hides an old record while retaining its ID and a `superseded_by` reference. The official docs describe deletion as soft and restorable; physical erasure and backup handling are not established by the inspected sources.[[database](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/db.ts)] [[memory documentation](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/mintlify-docs/tools/memory.mdx)]

**Retrieval.** Automatic recall and explicit tool search use semantic and full-text signals, with additional file and code-context signals available to ranking. Read scope determines which project/global databases participate. The agent can also list and retrieve records directly. Runtime accuracy, abstention, and write-to-recall delay were not evaluated.[[recall](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/recall.ts)] [[memory tool](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/tools/memory.ts)]

**Scope isolation.** Project and global memories live in separate files, and callers can configure write and read scopes, including project-only, global-only, both/all, and none. This partitions memory databases by scope, but the reviewed sources do not establish tenant authorization or isolation between processes that can access the same files.[[manager](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/manager.ts)] [[scope types](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/types.ts)] [[memory documentation](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/mintlify-docs/tools/memory.mdx)]

**Provenance and evidence.** Records retain user/agent source, session ID, timestamps, topics, and file references. These are attribution/context fields; the schema does not require source quotations, citation validation, or truth evaluation, and it has no explicit epistemic trust state.[[record types](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/types.ts)] [[database](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/db.ts)]

**Efficiency and observability.** SQLite indexes, FTS5, content-hash deduplication, offline embeddings, and bounded recall output are implementation choices. The schema tracks hint surface and action counts, and the memory browser supports cleanup review. These do not establish measured efficiency, operational monitoring, or a complete mutation audit. No latency, token, cost, or storage measurements were collected.[[database](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/db.ts)] [[recall](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/src/core/memory/recall.ts)] [[memory documentation](https://github.com/proxysoul/Empryo/blob/bc87cc125c2fa6246b76e09606a2d150ca33865f/mintlify-docs/tools/memory.mdx)]
