The repository README describes Elephantasm as an open-source, Python framework for long-term agent memory. It stores raw interaction events, synthesizes them into memories, extracts typed knowledge, and compiles a memory pack for prompt context. ## Architecture and data model

**Code observation.** PostgreSQL stores Animas (agent identities), Events, Memories, typed Knowledge, Identity records, MemoryPacks, and audit/session records. Events preserve raw content and metadata. Memories hold summarized and optional full content, importance, confidence, lifecycle state, time range, JSON metadata, and an optional 1,536-dimensional embedding. Knowledge records have one of five types (FACT, CONCEPT, METHOD, PRINCIPLE, EXPERIENCE), optional topic and confidence, source type, soft-delete state, and an optional embedding. The repository uses pgvector for semantic retrieval.[[events.py — raw event fields](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/events.py)] [[memories.py — memory fields and lifecycle](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/memories.py)] [[knowledge.py — typed knowledge fields](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/knowledge.py)]

The README describes a transformation pipeline: events are accumulated until a configurable score threshold, then a workflow asks an LLM to synthesize structured memories and generates embeddings; a second workflow extracts typed knowledge; a background Dreamer curation pass can merge, split, refine, or retire memories. Memory-to-event links are stored in a junction table, while knowledge audit rows can link a knowledge item to its source memory. Identity is a separate layer. These are architecture descriptions from docs and source, not measurements of quality or reliability.[[README.md — synthesis and knowledge extraction](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/README.md)] [[memory_persistence.py — memory creation and event links](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/workflows/memory_synthesis/nodes/memory_persistence.py)] [[memories_events.py — provenance junction](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/memories_events.py)] [[knowledge_audit_log.py — knowledge change and source fields](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/knowledge_audit_log.py)]

## Write, update, delete, and retrieval

**Code observation — writes.** The Events API accepts an event for an anima and schedules a background synthesis-threshold check when background jobs are enabled. Event creation records content, type, role/author, source time, session, metadata, source URI, deduplication key, and importance. Once synthesis runs, the workflow creates a Memory and MemoryEvent links together in an RLS-scoped transaction; embedding generation is best effort, so a failed embedding does not fail memory persistence. Knowledge synthesis then stores typed items associated with the source memory through audit provenance.[[events.py — event data model](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/events.py)] [[events.py route — event ingestion and scheduler trigger](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/api/routes/events.py)] [[memory_persistence.py — atomic memory and provenance persistence](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/workflows/memory_synthesis/nodes/memory_persistence.py)] [[knowledge_persistence.py — knowledge extraction persistence](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/workflows/knowledge_synthesis/nodes/knowledge_persistence.py)]

**Code observation — updates and deletion.** Memory endpoints support partial updates, soft deletion, and restoration; ordinary reads omit soft-deleted memories unless requested. Events have partial update and soft-delete operations, preserving rows for provenance. Knowledge has partial updates and soft deletion; its API creates audit entries for changes, and the audit model stores action, source type/source ID, before/after state, and trigger metadata. Dreamer mutations are represented by DreamAction records with snapshots and reasoning according to the repository README and domain model. These mechanisms retain records rather than proving complete erasure across backups, derived knowledge, embeddings, caches, or every storage surface. No universal deletion workflow was established by this bounded inspection.[[memory_operations.py — update, soft-delete, and restore](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/domain/memory_operations.py)] [[memories.py route — CRUD API](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/api/routes/memories.py)] [[events.py route — event update and soft delete](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/api/routes/events.py)] [[knowledge.py route — knowledge API and audit creation](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/api/routes/knowledge.py)] [[knowledge_audit_log.py — audit schema](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/knowledge_audit_log.py)] [[dreamer_operations.py — Dreamer operations](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/domain/dreamer_operations.py)]

**Code observation — retrieval.** The Pack Compiler assembles identity, recent session memories, semantically retrieved knowledge, and scored long-term memories. With a query it creates a query embedding; memory and knowledge retrieval apply anima and deletion filters, state/type or time filters, and similarity/score criteria. Retrieved memory records carry a reason and score breakdown in the compiled representation. The pack is the integration surface for prompt context; direct APIs also expose listing and text or semantic search. The compiler is synchronous and its source documentation says it makes no LLM calls during retrieval, although embedding lookup may call the configured embedding provider.[[memory_pack_compiler.py — pack layers and scoring](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/services/memory_pack_compiler.py)] [[memory_retrieval.py — time-windowed memory queries](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/domain/memory_retrieval.py)] [[knowledge_retrieval.py — vector retrieval](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/domain/knowledge_retrieval.py)] [[memory_packs.py route — query-aware compile and cached pack path](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/api/routes/memory_packs.py)]

## Scope isolation and provenance

**Code observation.** Events, memories, and knowledge carry an anima_id and their retrieval paths filter by that ID. Authenticated API routes obtain the user from a JWT or API key and create a database session with that user as RLS context; the route and dependency source describe database row-level policies as restricting access to the caller's owned data. Workflow helpers also establish user RLS context for synthesis operations. This is source evidence for an intended per-user/per-anima boundary, not an adversarial isolation test; no cross-user probes or deployment configuration review was performed.[[memory model — anima ownership key](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/memories.py)] [[memory retrieval — anima filter](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/domain/memory_retrieval.py)] [[RLS dependency — authenticated user context](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/core/rls_dependencies.py)] [[workflow RLS context](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/workflows/utils/rls_context.py)]

Memory provenance is represented by explicit memory/event links, with source event IDs retained alongside a memory. Knowledge audit records can connect an extracted knowledge item to its source memory and retain change snapshots. This makes lineage inspectable in the data model, but the inspected sources do not show that generated answers expose verifiable citations to original external passages or that every stored claim is checked against evidence.[[memories_events.py — memory/event links](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/memories_events.py)] [[knowledge_audit_log.py — knowledge source and snapshots](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/database/knowledge_audit_log.py)] [[README.md — lineage claims](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/README.md)]

## Source-visible efficiency and observability

**Code observation.** Retrieval is organized as bounded layers, uses stored embeddings and scoring filters, and the DTO supports a maximum token budget. The README describes an accumulation threshold to defer synthesis until enough time/events/tokens accrue; its example weights and thresholds are configuration defaults, not measured cost or delay. Source contains logging around synthesis, curation, and embedding failures, and persists pack records and synthesis/session data. These establish implementation structure and observability surfaces only. No operation latency, token usage, cost, storage bytes, throughput, or write-to-recall delay was measured.[[memory_pack_compiler.py — retrieval and pack construction](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/services/memory_pack_compiler.py)] [[retrieval.py DTO — token budget and scoring options](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/models/dto/retrieval.py)] [[README.md — thresholded synthesis configuration](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/README.md)] [[synthesis_metrics.py — source-visible metric operations](https://github.com/kaminocorp/elephantasm-core/blob/3dc935e52b1b98e40f386194a5f2b39489e42b85/app/domain/synthesis_metrics.py)]
