## Architecture and data model

**Code observation.** The schema defines one `memories` table. Rows include text content, 1536-dimensional embedding, one of nine memory types, nullable project namespace, tags, importance, source, extracted entities and free-form metadata, record timestamps, a validity window, optional expiry, a supersession pointer, active state, and access counters. Postgres provides HNSW cosine, generated English `tsvector`/GIN, trigram, entity, project/type, active and temporal indexes. The client calls OpenAI for `text-embedding-3-small`; optional named-entity extraction uses `gpt-4o-mini` and is skipped for short content or transcripts. No background index queue is used by the inspected client path.[[sql/schema.sql — `memories`, indexes, and `update_memories_updated_at`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)] [[src/client.js — `MemoryStore.embed`, `extractEntities`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/client.js)]

The repository includes an MCP server that exposes recall, store, timeline, history, and forget tools over `MemoryStore`. Tool definitions validate input and format results; database and embedding logic remain in the client and SQL.[[src/mcp-tools.js — `registerMemoryTools`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/mcp-tools.js)]

## Write, update, delete, and retrieval

**Write and duplicate handling — code observation.** `MemoryStore.store` embeds incoming content and checks for an active same-project, same-type semantic match using a default cosine threshold of 0.95. A match updates the existing row's content, importance, metadata, and tags; otherwise the client may extract entities, optionally retire a supplied `supersedes` ID, insert the new row, then set the old row's `superseded_by`. The SQL also defines a trigram snapshot-duplicate function for long recent fact/pattern rows, but the inspected `store` method does not call it. The near-duplicate update payload does not replace the stored embedding, so the new content and vector may diverge on that branch. Entity extraction catches failures and returns an empty list; embedding and database failures are surfaced.[[src/client.js — `MemoryStore.store`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/client.js)] [[sql/schema.sql — `find_similar_memory`, `find_snapshot_duplicate`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)]

**Correction and history — code observation.** A caller can create a replacement with `supersedes`; the client marks the old row inactive and closes `valid_until`, inserts the new row, and then links the old row to the inserted ID. `memory_history` returns text-matched rows with validity dates, `superseded_by`, and an `is_current` flag. This describes an explicit correction path; it does not show automatic correction detection, transactional guarantees across the sequence, or measured stale-value accuracy. The README says current preferences and corrections avoid recency decay, but correct post-correction answers were not measured.[[src/client.js — `store`, `history`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/client.js)] [[sql/schema.sql — `memory_history`, `search_memories`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)]

**Deletion — code observation and boundary.** `forget(id)` soft-deletes an active row by setting `active=false` and `valid_until`, while retaining the row for provenance. The inspected recall, timeline, dedup, and entity-search functions filter inactive rows. This is retirement from those query paths, not physical erasure: behavior for backups, external logs, copied data, or other downstream stores is not established. The schema has `expires_at`, but the inspected client exposes no expiry-specific delete/cleanup operation.[[src/client.js — `MemoryStore.forget`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/client.js)] [[sql/schema.sql — active filters and expiry in search/timeline](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)]

**Retrieval — code observation.** `recall` embeds the query and calls `search_memories`. The SQL gathers up to 50 cosine candidates and up to 30 OR-combined full-text matches; transcripts are excluded from the text lane. A named-entity lane can add up to 12 matching active memories. Candidates are fused with reciprocal rank fusion (`k=60`), then optionally blended with bounded recency, importance, prior access, and entity match factors. The function returns cosine similarity separately from its internal ordering score. Project, type, importance, similarity, date, expiry, and active filters are applied in the candidate queries. `track_access` defaults off in SQL but the client defaults it on, updating access counters for returned rows.[[sql/schema.sql — `search_memories`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)] [[src/client.js — `MemoryStore.recall`](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/client.js)]

**Scope and isolation.** The nullable `project` value is passed as an optional namespace filter. In SQL, a null filter means no project restriction, so an omitted project can search globally. The default schema enables row-level security with no policies, making the documented default server-only for anon/authenticated roles; the client is configured for a service key, which bypasses RLS. The separate `sql/rls.sql` file contains commented examples for per-user `auth.uid()` policies and a public read-only corpus. Those are opt-in templates, not enabled per-user isolation in the default schema. A project label is not itself an authenticated tenant boundary. No cross-scope probes or authorization tests were run.[[sql/schema.sql — `project` field and RLS enablement](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)] [[sql/rls.sql — optional RLS postures](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/rls.sql)] [[src/client.js — service-key client setup](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/client.js)]

**Provenance and evidence.** Returned rows include memory ID, content, type, project, tags, importance, source, creation time, metadata, and cosine similarity. The MCP formatter shows the ID, date, project, type, and similarity. The schema's `source` and `metadata` fields can carry provenance context, and history exposes replacement links. The inspected interfaces do not automatically attach source-session pointers or resolvable citations to factual claims in generated answers. Claim-level evidence support is unknown.[[sql/schema.sql — `memories` and `search_memories` return fields](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/sql/schema.sql)] [[src/mcp-tools.js — result formatting](https://github.com/reescalder/agent-memory-supabase/blob/a67f2bb3bc7f0b2084fc63531acbc99b7c259f2e/src/mcp-tools.js)]
