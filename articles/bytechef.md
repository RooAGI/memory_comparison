## Summary

ByteChef is a self-hostable workflow automation platform that exposes both chat-memory backends and a document knowledge base to AI-agent workflows. The inspected knowledge-base component loads, transforms, indexes, filters, and retrieves document chunks through a shared pgvector store, while ordinary chat history uses separately configured Spring AI memory backends. This review describes source-visible design and does not assess runtime quality or performance. [[official README](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/README.md)] [[knowledge-base component](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/KnowledgeBaseComponentHandler.java)]

## Who and what

The official README presents ByteChef as an open-source AI-agent and workflow platform maintained by the ByteChef team. It lists eight chat-memory backends and a built-in knowledge-base/vector-store path; these are distinct integration choices rather than one unified memory store. This source review focuses on the built-in document knowledge base and notes chat-memory backends only where the README describes them. ## Architecture and data model

The knowledge-base component is registered as a vector-store component with load, search, update, and delete actions, plus corresponding agent cluster elements. It uses a platform knowledge-base service layer and a shared Spring AI vector store; README setup guidance says the knowledge base requires PostgreSQL with pgvector and does not support migration from the evaluation-only H2 setup. [[component wiring](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/KnowledgeBaseComponentHandler.java)] [[official README](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/README.md)]

A knowledge-base record carries its ID, name, description, environment, tags, optimistic version, and chunking settings. The inspected defaults are maximum chunk size 1024, minimum chunk size 100 characters, and overlap 200. A document record carries its knowledge-base ID, name, file-storage entry, status (uploaded, processing, ready, or error), size, tags, actor and timestamps, and version. [[knowledge-base model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBase.java)] [[document model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBaseDocument.java)]

A chunk record links to its parent document and stores a vector-store ID plus a file-storage entry for chunk content. Search-populated text, metadata, and score are transient fields on the chunk model. The vector-store adapter carries knowledge-base, document, chunk, and environment IDs in metadata; tag flags and caller-supplied metadata can accompany them. The source paths show the records and adapter boundary, not a complete deployment-specific placement of every object. [[chunk model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBaseDocumentChunk.java)] [[vector-store adapter](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStore.java)] [[scope wrapper](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStoreWrapper.java)]

## Write, update, delete, and retrieval

**Write and transform.** The load action selects a knowledge base and invokes a document reader followed by configured splitter/enricher transformers before sending the resulting documents through the vector-store adapter. The knowledge-base vector-store component uses one shared pgvector index and a globally configured embedding model rather than accepting a per-component embedding element. [[load action](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/action/KnowledgeBaseLoadAction.java)] [[vector-store adapter](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStore.java)]

**Update.** The update action accepts a document or chunk target (or multiple targets), readers and transformers, and metadata filters. The adapter removes existing chunk records and matching vector entries before loading replacement content; document-level updates can retain other metadata from an existing chunk and overlay additional metadata. This is replacement behavior, not an inspected content-version history or tombstone model. [[update action](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/action/KnowledgeBaseUpdateAction.java)] [[vector-store adapter](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStore.java)]

**Delete.** The delete action removes documents selected by metadata filter. The wrapper combines metadata-filter deletes with the knowledge-base ID predicate. Physical deletion across database backups, external file storage retention, and vector-store replicas was not verified. [[delete action](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/action/KnowledgeBaseDeleteAction.java)] [[scope wrapper](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStoreWrapper.java)]

**Retrieval.** A nonblank query uses semantic vector similarity; top-K defaults to 10 and similarity threshold defaults to 0.0. Optional tags use OR semantics. With an empty query, tag or metadata filters can drive a filter-only result path; metadata conditions within a group are AND-ed and groups are OR-ed. The wrapper always ANDs the knowledge-base ID with query filters, tags, and caller filters. [[search action](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/action/KnowledgeBaseSearchAction.java)] [[scope wrapper](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStoreWrapper.java)]

**Scope isolation.** The source-visible search boundary constrains vector similarity retrieval to the selected knowledge-base ID, and metadata-filter deletion also combines that ID. This demonstrates a query-level scope predicate. The inspected component slice does not establish end-to-end tenant authorization, caller identity enforcement, or isolation for every direct vector-store call; no cross-tenant tests or probes were run. [[scope wrapper](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStoreWrapper.java)] [[component wiring](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/KnowledgeBaseComponentHandler.java)]

**Provenance and evidence.** Stored document and chunk models preserve document/chunk IDs, file-entry references, tags, environment, created/modified actor and time, and optimistic version values. Search results can include transient metadata and similarity scores. These fields provide object linkage and retrieval context; the inspected paths do not establish answer-level source citations, claim verification, or evidence-support precision. [[document model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBaseDocument.java)] [[chunk model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBaseDocumentChunk.java)] [[vector-store adapter](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStore.java)]

**Source-visible efficiency and observability.** Source exposes chunk sizing/overlap, query top-K, similarity threshold, optional metadata/tag filters, and a single shared embedding configuration. The adapter computes byte counts for load/update accounting, while document status has uploaded, processing, ready, and error states. These are code-visible controls and state fields, not latency, throughput, cost, token, or storage measurements. [[knowledge-base model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBase.java)] [[search action](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/action/KnowledgeBaseSearchAction.java)] [[vector-store adapter](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/modules/components/ai/vectorstore/knowledgebase/src/main/java/com/bytechef/component/ai/vectorstore/knowledgebase/util/KnowledgeBaseVectorStore.java)] [[document model](https://github.com/bytechefhq/bytechef/blob/93adcdf6635bc944816ad18fdf39c7ae472f5e87/server/libs/platform/platform-knowledge-base/platform-knowledge-base-api/src/main/java/com/bytechef/platform/knowledgebase/domain/KnowledgeBaseDocument.java)]
