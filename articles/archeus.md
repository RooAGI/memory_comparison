## Summary

Archeus is a local workspace and memory layer for coding agents. It builds a per-project semantic graph from repository files and session transcripts, then exposes compact project memory through a launcher digest, path-scoped rules, and optional prompt-time retrieval. A separate lesson pipeline extracts durable decisions and corrections from sessions.[[README](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/README.md)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)]

## Who and what

The repository identifies Babar Muhammad Anas as the project author. Archeus is a MIT-licensed local Python application, rather than a standalone memory service: the project memory feature is integrated with its terminal UI, desktop GUI, and Claude Code plugin. The README also describes compatibility with OpenAI Codex and pi.[[README](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/README.md)] [[repository page](https://github.com/babarmuhammad/archeus)]

## Architecture and data model

**Code observation.** `claude_sessions.memory` stores a versioned JSON graph in the project work directory under `.archeus/memory/graph.json` and mirrors it into Archeus's encoded project folder when available. The graph includes entities, relations, repository/module summaries, source provenance, module dependency edges, lesson scan state, conflicts, staleness fields, and aggregate model-call cost fields. Saves use an atomic JSON helper; a graph shrink can record a snapshot first.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)]

**Code and documentation observation.** Background refresh extracts bounded source-file and module content with a headless model call, incrementally using file state and content hashes, then merges results with dependency information. Source constants cap per-file and per-batch input and representative files per module. A per-project exclusive scan lock coordinates refresh work. The guide describes capped background cycles, queued work, visible progress, and saving progress between steps.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)]

The guide describes three context surfaces: a small always-on CLAUDE.md micro-index, lazy per-module `.claude/rules/` files, and an optional UserPromptSubmit hook that injects a task-related subgraph. Recall ranking is local lexical work; the prompt path does not call a model to rank every query. The guide also describes a separate worklog that can add a small number of recent session episodes.[[README](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/README.md)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)] [[recall implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/recall.py)]

## Write, update, delete, and retrieval

**Write/build — code observation.** A memory build scans source files and sends bounded module content to the configured headless model for entities and relations; it also incorporates dependency edges and repository/module summaries. Refresh is incremental. The inspected memory and recall modules expose build/refresh behavior; a general per-fact user-authored CRUD API was not established in those files.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)]

**Update — code observation.** When refreshed code no longer supports a fact, the graph can mark it invalid and record its invalidation time instead of immediately removing it. Recall excludes invalid entities. The source bounds invalidated history by count and age; graph loss can be snapshotted before save, and the guide describes a 12-version history.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[recall implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/recall.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)]

**Delete/forget — inspection boundary.** The inspected model includes eviction and graph-shrinking paths, and the guide describes pruning with preview/confirmation and undo through snapshots. I did not establish a universal per-entity hard-delete API or physical erasure across snapshots, sidecars, mirrored copies, transcripts, or backups from the bounded files reviewed.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)] [[lesson eviction](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/lessons.py)]

**Retrieval — code observation.** Recall builds a local index over names and summaries; it combines lexical overlap, path/module matches, dependency rank and lesson confidence with reciprocal-rank fusion, then expands selected items through relations. Invalid facts and pending lessons are excluded. The renderer fits complete items within the remaining token budget instead of truncating a long item, and blank queries or empty graphs return no context.[[recall implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/recall.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)]

**Session lessons.** Lesson extraction asks the configured model to distill a bounded set of durable error/fix pairs, decisions, corrections, and preferences from session transcript tails. Lessons carry kind and confidence. People may approve, pin, or evict them; recall injects only approved or pinned lessons. The guide describes confidence-based auto-approval as a setting.[[lesson implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/lessons.py)] [[recall implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/recall.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)]

**Scope isolation.** The graph is selected by project path and encoded project folder, so normal code memory is project-oriented. Lesson scans include sessions for that project across accounts; convention processing intentionally scans project graphs across accounts. Recurring preferences, corrections, or decisions may be promoted into a user-level CLAUDE.md shared across projects. This is an explicit scope expansion for conventions.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[lesson implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/lessons.py)] [[convention implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/conventions.py)]

**Provenance and evidence.** Graph provenance and refresh state track source files/modules processed; session lessons originate from transcript sessions. Retrieved text includes entity names, summaries, and associated files where available. The inspected schema does not provide claim-level citations to source passages or an evidence adjudication protocol, so source lineage alone does not prove a statement is supported.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[recall implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/recall.py)] [[lesson implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/lessons.py)]

## Limits and unknowns

This is a bounded review of the pinned README, project-memory guide, memory/recall/lesson/convention implementation, and security policy. It does not establish runtime behavior or cover every UI, plugin, storage, and session subsystem. Retrieval quality, abstention, latency, refresh delay, cost, storage growth, and concurrent-load behavior remain unknown because no runtime or benchmark was run.

The inspected graph provides source/module lineage but not claim-level citations. The review cannot establish whether extracted statements are correct or whether a retrieved summary is supported by the referenced source. Physical deletion across snapshots, mirrored graphs, sidecars, transcripts, and backups was not established. Cross-project conventions deliberately broaden the audience for some learned content.[[memory implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/memory.py)] [[project memory guide](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/docs/memory.md)] [[convention implementation](https://github.com/babarmuhammad/archeus/blob/3fc3711c0b54aee9596c2e2a1ec5fd6b5d6d40c4/claude_sessions/conventions.py)]
